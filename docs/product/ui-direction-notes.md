# 界面方向记录

来源：用户提供的 Workspace Hub 界面参考图

记录日期：2026-06-07

这张界面参考图可以作为当前产品的第一版视觉和信息架构方向。整体风格是轻量、干净、偏 SaaS 工具型的桌面应用界面，主色使用蓝色，背景以白色和浅灰为主，卡片和面板边界清晰，整体重点是让用户快速看到当前工作区、当前工作区内的软件、白板记录和软件添加入口。

需要先明确一个边界：图中间区域看起来像是在产品内部显示浏览器页面，但按照前面已经确认的产品需求，第一版不应该承诺把任意外部软件嵌入到本应用内部。这个区域后续应理解为“当前工作区概览 / 当前软件预览 / 最近窗口截图 / 快捷入口区域”，而不是完整的外部软件容器。用户点击软件后，产品仍然负责切换到外部真实窗口。

## 1. 整体布局

界面采用三栏结构。最左侧是产品级导航和工作区列表，中间是当前工作区主操作区，右侧是白板和操作记录区。这个结构比单纯把所有软件都放在最左侧更清晰，因为它把“工作区切换”和“当前工作区软件管理”分开了。

左侧栏顶部展示品牌和产品名，例如 Workspace Hub。左侧主体展示工作区列表，每个工作区用卡片呈现，包含图标、工作区名称、文件/软件数量、最近更新时间和更多操作入口。当前选中的工作区需要有明显高亮边框或背景。左侧顶部有“新建工作区”按钮，底部可以放“归档工作区”入口。

中间区域顶部展示当前工作区名称，例如“产品设计工作区”，旁边有下拉箭头用于切换或管理当前工作区。标题右侧展示保存状态和最近保存时间。再右侧是全局或当前工作区搜索框、“添加软件”按钮、“工作区设置”和更多菜单。

中间主区域上方有当前工作区的软件/分类标签，例如“概述、文档、设计工具、终端、聊天、+”。这些标签不一定表示真实内嵌页面，可以表示当前工作区中已经加入的软件分类或软件快捷入口。点击标签时，如果对应外部软件窗口存在，应切换到该窗口；如果不存在，应提供重新打开入口。

右侧是白板 / 操作记录区。它是这款产品区别于普通 launcher 的关键区域。右侧上半部分展示白板卡片，例如便签、待办、截图或 Markdown 卡片；右侧下半部分展示操作记录时间线，用于用户手动记录某个时间点使用了哪个软件、做了什么事情。

## 2. 工作区列表

左侧工作区列表采用卡片式设计。每个工作区卡片包含一个彩色图标、名称、简短状态信息和最近更新时间。当前选中的工作区用蓝色边框和浅色背景强调。这个设计适合快速区分不同项目，例如产品设计、论文写作、数据分析、项目管理、个人知识库、学习笔记、市场调研。

这个区域承担的是“切换工作区”的职责，而不是展示当前工作区内所有已打开软件。当前工作区内的软件可以放在中间顶部的软件标签、添加软件面板和底部软件窗口卡片中。也就是说，后续 PRD 里“左侧只展示当前工作区的软件”需要根据这个界面方向调整：最左侧展示工作区列表，当前工作区的软件展示在主区域内。

## 3. 添加软件交互

截图中“添加软件”按钮位于顶部右侧，点击后出现下拉面板。面板标题是“添加软件到工作区”，说明文字强调“点击软件图标，即可打开并加入当前工作区”。这个交互符合前面需求，可以作为第一版的核心路径。

添加软件面板中按照软件类型展示系统扫描结果，例如浏览器、文档、表格、终端、设计工具、聊天、文件管理器、日历。每一项包含图标、软件名称和“添加”按钮。点击“添加”后，产品启动该软件，并将它加入当前工作区的软件集合。底部有“查看更多软件”入口，用于打开完整软件库或搜索全部已扫描软件。

这个面板的重点不是做成复杂应用商店，而是做成接近系统搜索的快速启动器。后续实现时应支持搜索过滤、系统扫描结果、手动添加 exe/快捷方式/文件夹/网址/命令，以及已加入软件的状态展示。

## 4. 当前工作区软件展示

当前工作区的软件可以通过三种方式展示。第一种是顶部标签，适合展示最常用或当前正在使用的软件分类。第二种是底部软件卡片，截图里有“文档 - 竞品整理”“设计工具 - 首页原型”“终端 - 前端开发”“聊天 - 团队讨论”等卡片，每张卡片包含标题、关闭按钮和缩略预览。第三种是添加软件面板中的已添加状态。

底部软件卡片是一个很有价值的设计。它比单纯图标更能恢复上下文，因为用户能看到这个软件在当前工作区里的用途，而不只是看到“Chrome”或“VS Code”。实现时可以先用软件图标、名称和用户自定义备注替代真实缩略图；后续再考虑窗口截图预览。

如果同一个软件在不同工作区都被加入，展示应以工作区维度隔离。同一个 Chrome 在“产品设计工作区”里可以叫“竞品分析”，在“论文写作”里可以叫“文献检索”。这说明软件实例需要有工作区内别名或用途备注，而不是只保存系统软件名称。

## 5. 白板与操作记录

右侧白板区域由便签式卡片和时间线组成。便签卡片适合记录工作目标、待办事项、关键截图、检查清单和临时想法。时间线适合记录用户手动写下的操作过程，例如 10:30 使用浏览器查看竞品页面，10:05 使用文档整理需求，09:40 使用设计工具绘制首页原型。

这个设计比纯白板更适合你的产品，因为它把“自由记录”和“按时间恢复上下文”结合起来。第一版可以把白板分成两个层次：上半部分是可拖拽卡片，下半部分是结构化操作记录。操作记录不需要自动监听外部软件行为，仍然由用户手动添加或在切换软件时提供快捷记录入口。

白板底部工具栏包含选择、拖动、文字、便签、矩形、画笔、颜色等工具。第一版可以简化为选择、文本/Markdown 卡片、图片/截图卡片、待办卡片、颜色标记和撤销重做。画笔和复杂绘图不是 MVP 必须项。

## 6. 顶部状态与搜索

顶部状态区显示“已保存”和“最近保存时间”，这对本地工作区产品很重要。用户会在白板中不断记录内容，因此自动保存状态必须明确，避免用户担心内容丢失。

搜索框文案可以是“搜索工作区内内容”。它应该优先搜索当前工作区内的软件、白板卡片、操作记录和备注。未来可以扩展到全局工作区搜索，但第一版更应该做好当前工作区内搜索。

“工作区设置”入口用于管理工作区名称、图标、颜色、默认软件、启动行为、白板保存位置和是否归档。“更多”菜单可以放导出、复制工作区、删除工作区等低频操作。

## 7. 视觉风格记录

视觉方向是现代桌面生产力工具风格，关键词是清爽、轻量、低干扰、明确分区。按钮和选中态以蓝色为主，工作区图标可以使用不同颜色帮助区分。卡片使用浅边框、轻阴影和 8px 左右圆角。界面信息密度中等偏高，不做营销式大标题，也不做过度装饰。

主界面应避免过多大面积插画或空状态文案，因为这是一个高频使用的工作工具。真正重要的是工作区切换、软件启动、窗口切换和白板记录的速度。视觉可以精致，但不能牺牲信息可扫读性。

## 8. 与当前 PRD 的调整点

这张图对原始 PRD 有一个明显修正：左侧不再直接展示当前工作区的软件，而是展示工作区列表。当前工作区的软件被放在主区域顶部标签、添加软件面板和底部软件卡片中。这个调整是合理的，因为产品需要同时支持多个工作区，如果左侧只放当前工作区软件，工作区切换入口会变弱。

另一个需要坚持的边界是：中间的浏览器画面不应被解释为外部软件内嵌。为了避免后续开发误解，文档中应该统一表述为“当前窗口预览、最近截图或工作区概览”，真实操作仍发生在外部软件窗口中。

后续产品文档应以这个界面方向为准：左侧工作区列表，中间工作区软件与预览，右侧白板/操作记录，顶部搜索和添加软件。这样既符合截图的视觉结构，也不破坏前面确认过的技术边界。
