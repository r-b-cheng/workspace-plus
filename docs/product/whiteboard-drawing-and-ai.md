# 白板画图与 P2 画布 AI

制定日期：2026-08-21

白板现在是 Obsidian Canvas 式卡片：Markdown、图片、卡片之间的箭头。这适合记笔记和整理关系，但还不能当一块能画画的板，笔记也不能改字号。

P2 的最终形态不是再做一份自动摘要，而是：**用户和 AI 对着同一块白板说话**。AI 能读当前工作区的卡片、连线和手绘，能在白板上补图、补箭头、补卡片，再和用户讨论。它只看用户放进白板的东西，不读外部软件内部内容。

本文同时约束三件事：笔记字号、用户画图、P2 对话式 AI。实现分包见文末。

## 1. 现在缺什么

1. Markdown 卡片的编辑器和预览都写死了约 13px，用户改不了笔记字号。
2. 用户不能在空白处画笔、箭头、框。现有箭头只是卡片连卡片。
3. 还没有对话面板。已规划的 pkg-14 是手动总结，pkg-15 是费曼追问，都还没覆盖「边聊边画」。

## 2. 笔记字号（现在做，不另开大包）

字号是卡片级属性，不是选中几个字再设 span。笔记仍是 Markdown，不把编辑器改成富文本。

- 每张 Markdown 卡片可选：13 / 16 / 20 / 24。默认 13，和现在一致。
- 编辑器和预览用同一个字号。标题、列表仍按 Markdown 相对放大。
- 写在该节点的 `metadataJson`：`{"fontSize":16}`。不新增数据库列。
- 卡片顶栏提供字号选择。`data-testid`：`markdown-font-size-{nodeId}`。
- 不在本轮做：选中文字改字号、自定义任意 px、改图片卡片字号。

## 3. 画图怎么做

### 3.1 不换主白板

继续用 React Flow / xyflow 放卡片和卡片连线。不把整张白板换成 Excalidraw，也不引入 tldraw（生产授权要 license key，见 `docs/process/open-source-reuse-research.md`）。

工程规格里写过：Excalidraw 适合以后做手绘模块，不是第一版主白板。这个判断仍然成立。缺的是**旁边再加一层可画的 scene**，不是推翻卡片模型。

### 3.2 两层，一份自己的 JSON

每个工作区有两份数据，存在一起，镜头共用：

| 层 | 存什么 | 表 / 字段 |
|---|---|---|
| 卡片层 | Markdown、图片、卡片连线 | 已有 `canvas_nodes` / `canvas_edges` |
| 画图层 | 笔迹、形状、自由箭头、贴在画布上的短字 | 新表 `canvas_scenes`，一区一行，`scene_json` |

画图不存 XML，也不把 React Flow 的选中、拖拽字段塞进库。scene 用版本化 JSON，模型和人都能读写：

```json
{
  "version": 1,
  "elements": [
    {
      "id": "el-1",
      "type": "path",
      "points": [[120, 80], [160, 90], [210, 70]],
      "color": "#176bff",
      "strokeWidth": 2
    },
    {
      "id": "el-2",
      "type": "arrow",
      "x1": 80,
      "y1": 120,
      "x2": 240,
      "y2": 160,
      "color": "#172033",
      "strokeWidth": 2
    },
    {
      "id": "el-2b",
      "type": "line",
      "x1": 80,
      "y1": 200,
      "x2": 240,
      "y2": 200,
      "color": "#172033",
      "strokeWidth": 2
    },
    {
      "id": "el-3",
      "type": "rect",
      "x": 300,
      "y": 40,
      "width": 160,
      "height": 90,
      "color": "#176bff",
      "fill": null
    },
    {
      "id": "el-4",
      "type": "text",
      "x": 320,
      "y": 70,
      "text": "入口",
      "fontSize": 16,
      "color": "#172033"
    }
  ]
}
```

坐标和卡片一样，是画布世界坐标，不是屏幕像素。缩放、平移只改镜头，不改已存点。

第一刀 `type`：`path`、`line`、`arrow`、`rect`、`ellipse`、`text`。`line` 是没有箭头的直线；按住 Shift 可锁成横线或竖线。`text` 在选了「字」后单击空白处出现输入框，或在选择模式下双击空白处。输入框不能被同一次点击的 `blur` 立刻关掉。不做：位图笔刷、图层混合、钢笔贝塞尔调节点、激光笔。

### 3.3 工具和命中

白板工具栏增加模式，一次只激活一种：

- **选择**：拖卡片、拉卡片连线、点选/删除画图元素。指针打在卡片层和已有图形上。
- **画笔**：在空白处画出 `path`。
- **箭头 / 直线 / 矩形 / 椭圆 / 字**：在空白处落下对应元素。直线没有箭头；按住 Shift 锁成横线或竖线。

画图模式下，卡片不要跟着被拖走。选择模式下，点在笔迹上不要误拖底下的卡片。实现上按模式切 `pointer-events`，两层共用 React Flow 的 viewport（`x / y / zoom`）。

删除：选中图形后 Delete / Backspace。撤销重做本包能做一层本地栈最好，做不完就先保证删除和自动保存。

矩形和椭圆的描边默认用产品黑 `#172033`（和直线、字一致），填充仍透明。不要再默认画成蓝色。已经存成别的颜色的旧图形保持原色。

### 3.3.1 选择后的移动与变形

选择模式下，画上去的物体要能像常见白板一样改，不能画完就钉死。

- **点选**：单击图形选中。选中后画虚线包围盒。点空白取消。一次只操作一个图形（本轮不做框选多选）。
- **移动**：按住图形本体拖。超过约 4px 才算拖，避免和单击抢。光标用 `grab` / `grabbing`。方向键微移 1 单位，Shift+方向键 10 单位；焦点在输入框时不要抢。
- **矩形 / 椭圆**：包围盒四角和四边中点共 8 个手柄。拖手柄改 `x/y/width/height`。按住 Shift 锁定宽高比（正方形 / 正圆）。最小边长 4。
- **直线 / 箭头**：两端各一个手柄，拖端点改形状；按住 Shift 仍锁横竖。拖线身则整体平移。
- **笔迹**：按包围盒整体平移；拖角手柄等比缩放全部点。不提供逐点调钢笔。
- **字**：拖文字移动；拖角手柄改 `fontSize`（下限 10）。
- 手柄大小按镜头补偿（屏幕上大约 8px），不要缩得很小时点不到。
- 变形只改 scene 元素的几何字段，走现有自动保存。不要把选中、手柄、dragging 写入 JSON。
- 拖图形时不要拖走底下的卡片。卡片照旧只在没点到图形时拖。

### 3.4 为什么不用整份 Excalidraw JSON

Excalidraw 元素字段多，模型生成时容易编造内部字段，合并也难。我们自己的 `elements` 更短，P2 的 AI 只要返回「增 / 改 / 删」补丁：

```json
{
  "op": "upsert",
  "elements": [{ "id": "el-9", "type": "arrow", "x1": 10, "y1": 10, "x2": 80, "y2": 40 }]
}
```

以后若要导出成图片或兼容 Excalidraw，再做转换，不要把对方的文档格式当成库表。

## 4. P2：对着白板对话

P2 的 Agent 主路径是对话，不是定时摘要。

用户在当前工作区打开对话。模型看到的只有用户允许的范围：选中卡片、当前视口，或整张白板。材料包括：

- Markdown 标题和正文
- 图片卡片标题（不把整张图默认塞进每次请求；用户明确要求看图时再带）
- 卡片连线（谁指向谁、线上的字）
- 画图层：形状种类、位置、箭头两端、`text` 元素正文

模型可以：

1. 用中文讨论、追问、解释。
2. 建议并写入新的 Markdown 卡片（和今天的卡片一样，可改、可删）。
3. 往 `scene_json` 追加或修改元素（画框、画箭头、标字）。
4. 费曼式追问（已规划的 pkg-15）仍可用，作为对话里的一种模式，而不是唯一入口。

默认不自动打模型。没有配置 provider 时，指引去设置，不要静默失败。密钥不进白板表、不进日志、不进导出包。

不读外部软件内部文档、网页、编辑器缓冲区。预览模式里的记事本内容也不自动进上下文。

生成的卡片和图形都是普通白板对象。用户删掉即撤销这次写入。AI 不得覆盖用户没点确认的原文；第一刀采用「先写入新对象，不改旧卡片」。若以后做「改现有图」，必须先标出将改哪些 id，并允许取消。

## 5. 和现有 P2 包怎么排

| 包 | 角色 |
|---|---|
| 笔记字号 | 现在做。走已有 `metadataJson`，不开新包。 |
| [pkg-21](../dev-plan/packages/pkg-21-whiteboard-drawing/) | 用户画图。工具栏、scene JSON、和卡片共用镜头。**AI 会画的前提。** |
| [pkg-14](../dev-plan/packages/pkg-14-ai-canvas-summary/) | 第一刀 AI：手动总结。上下文先吃卡片和连线；21 完成后把 scene 摘要加进去。 |
| [pkg-15](../dev-plan/packages/pkg-15-feynman-agent/) | 费曼追问。材料同样只来自白板。 |
| [pkg-22](../dev-plan/packages/pkg-22-ai-canvas-chat/) | 对话面板：边聊、边读白板、边往 scene / 卡片上落笔。依赖 14 的 provider 与上下文，依赖 21 的 scene。 |

pkg-13 到 pkg-18 仍按此前决定暂缓。画图和对话不从那几包里「顺便」做掉。

## 6. 验收口径

字号：新开 Markdown 卡片能改字号；预览和编辑一致；重启后还在。

画图（pkg-21）：能画一笔、一个箭头、一个框；缩放平移后位置不错；重启后还在；工作区 A 的图不会出现在 B。

对话（pkg-22）：一次手动对话能引用当前卡片或当前图；模型画出的箭头出现在画图层且可删；默认不自动请求；密钥不进画布。
